# Connect team handbook

This folder turns the course rules into daily team actions.

| Document | Use it for |
|---|---|
| [PRODUCT-LEAD.md](PRODUCT-LEAD.md) | scope, priorities, user stories and backlog |
| [DESIGN-LEAD.md](DESIGN-LEAD.md) | flows, wireframes, states and UI consistency |
| [DEVELOPMENT-LEAD.md](DEVELOPMENT-LEAD.md) | architecture, integration, builds and technical decisions |
| [QUALITY-LEAD.md](QUALITY-LEAD.md) | acceptance criteria, tests, defects and quality evidence |
| [GITHUB-WORKFLOW.md](GITHUB-WORKFLOW.md) | issues, branches, commits, pull requests and reviews |
| [TESTS-AND-CHECKS.md](TESTS-AND-CHECKS.md) | what must be checked and when |
| [RESPONSIBILITIES.md](RESPONSIBILITIES.md) | responsibilities shared by the whole team |
| [ROLE-ROTATION.md](ROLE-ROTATION.md) | stage assignments and handovers |
| [TASKS-AND-CHECKLISTS.md](TASKS-AND-CHECKLISTS.md) | current work queue and Definitions of Ready/Done |
| [COURSE-ROADMAP.md](COURSE-ROADMAP.md) | course-aligned implementation order |
| [ARCHITECTURE.md](ARCHITECTURE.md) | allowed dependencies and future Firebase placement |

Leads coordinate their areas; they are not the only people who work in them. Every member contributes to research, design, implementation, testing and documentation.
