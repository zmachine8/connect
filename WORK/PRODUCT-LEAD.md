# Product Lead

## Accountable for

- product direction, priorities and stage scope;
- alignment between the report, GitHub backlog and implemented application;
- clear user stories and acceptance outcomes;
- stopping scope creep;
- ensuring every ready task has an owner.

Connect's priority order is **account/login → users → text chat → photos**. Feeds, likes, comments, stories, calls, groups, recommendations, ads and monetisation stay out of scope.

## Regular behaviour

### At the start of a week

- [ ] Review milestones and deadlines.
- [ ] Put the most valuable small issues in `Ready`.
- [ ] Confirm that each issue describes user value and acceptance criteria.
- [ ] Assign an owner without assigning the entire issue to a Lead automatically.
- [ ] Remove or postpone work that is not needed for the current stage.

### During work

- [ ] Answer scope questions quickly.
- [ ] Compare proposed additions against the MVP.
- [ ] Keep GitHub status accurate.
- [ ] Escalate blocked dependencies to the Development or Design Lead.

### Before a stage handover

- [ ] State what is complete, incomplete and intentionally deferred.
- [ ] Link the relevant issues and pull requests.
- [ ] Record product risks and the first decision required from the next Lead.

## Good user story

> As a registered user, I want to see other registered users so that I can choose someone to message privately.

Do not write a story as “implement LazyColumn.” That is a technical task, not user value.
