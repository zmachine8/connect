# Team responsibilities

A Lead is the person accountable for coordinating an area, not the only person who performs its work.

Every team member must:

- [ ] Pull the latest `main` before starting.
- [ ] Work from a GitHub Issue.
- [ ] Use a short-lived branch for a coherent change.
- [ ] Make small commits with clear messages.
- [ ] Push work regularly so contribution is visible.
- [ ] Run relevant tests before requesting review.
- [ ] Review teammates' work when requested.
- [ ] Update documentation when behaviour or setup changes.
- [ ] Continue fixing defects in work they previously produced.
- [ ] Participate in research, design, implementation, testing and documentation.
- [ ] Credit third-party code, libraries, APIs, images and icons.
- [ ] Follow UT rules for AI-assisted work and understand submitted code.

## Communication rule

If a decision changes scope, user experience, architecture, acceptance criteria or a deadline, record it in GitHub. Chat messages alone are not durable project documentation.
